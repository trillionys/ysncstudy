# Google Play 업로드 가이드 — CPA Concept Lab 1.0.8 (무료 앱)

모든 답은 실제 앱 구현(1.0.8)을 기준으로 작성했다. Play Console 화면 이름·질문은 바뀔 수 있으니 업로드 시점 화면을 기준으로 맞춰 입력한다.

## 0. 준비물 (이 폴더)
| 파일 | 용도 | 규격 |
|---|---|---|
| `CPAConceptLab-1.0.8-release.aab` (별도 전달) | 앱 번들 업로드 | 업로드 키 서명, versionCode 9, targetSdk 36 |
| `upload-keystore.jks` + 비밀번호 (별도 전달) | 업로드 키 — **절대 분실·공유 금지** | PKCS12, RSA 4096, 유효기간 2054-04-12 |
| `graphics/icon/app-icon-512.png` | 앱 아이콘 | 512×512, 32비트 PNG |
| `graphics/feature/feature-graphic-1024x500.png` | 그래픽 이미지 | 1024×500, 24비트 PNG |
| `graphics/screenshots/phone/captioned/*.png` (8장) | 휴대전화 스크린샷(권장) | 1080×1920, 24비트 PNG |
| `graphics/screenshots/phone/raw/*.png` (8장) | 설명 문구 없는 원본(대체용) | 1080×1920 |
| `graphics/screenshots/tablet7/…` (5장), `tablet10/…` (4장) | 7·10인치 태블릿(선택) | 1200×1920, 1600×2560 |
| `listing/*.txt` | 이름·간단한 설명·자세한 설명·출시 노트 | 25/30, 46/80, 1,378/4,000, 163/500자 |
| `privacy-policy.html` | 개인정보 처리방침 공개 URL 용 | — |

모든 그래픽은 `tools/store/make_store_assets.py` 로 생성·검증했다(36/36 통과). 스크린샷은 실제 앱 화면이며, 진도가 0%로 보이지 않도록 촬영 전에 예시 학습기록을 넣었다(`StoreScreenshotTest`).

## 1. 업로드 키 보관 (가장 중요)
- `upload-keystore.jks` 와 비밀번호를 두 곳 이상(예: 비밀번호 관리자 + 오프라인 USB)에 보관한다. 이 작업 환경(클라우드 컨테이너)은 곧 사라진다.
- Git 에는 커밋하지 않았다(`.gitignore`: `*.jks`, `keystore.properties`).
- 다음 업데이트를 빌드하려면 프로젝트 루트에 `upload-keystore.jks` 와 아래 `keystore.properties` 를 두고 `./gradlew bundleRelease`.
  ```
  storeFile=upload-keystore.jks
  storePassword=(전달받은 비밀번호)
  keyAlias=upload
  keyPassword=(같은 비밀번호)
  ```
- 업로드 키 인증서 SHA-256: `F2:73:78:57:8B:C9:77:78:35:6D:66:F6:8D:B6:82:BC:77:1E:12:8E:19:6C:10:E2:97:EA:61:AF:49:85:01:A6`
- 분실해도 **Play 앱 서명**을 쓰면 Play Console 에서 업로드 키 재설정을 요청할 수 있다(실제 앱 서명 키는 Google 이 보관).

## 2. 개인정보 처리방침 URL 만들기 (필수)
Play 는 누구나 열 수 있는 URL 이 필요하다. 하나를 고른다.
- **Google Sites**(무료): 새 사이트 → `privacy-policy.html` 본문 붙여넣기 → 게시 → 주소 복사
- **GitHub Pages**: 공개 저장소에 `privacy-policy.html` 을 올리고 Pages 활성화(현재 저장소가 비공개면 별도 공개 저장소 권장)
처리방침에는 운영자 연락처를 "Play 등록정보의 개발자 이메일"로 적었다. Play Console 의 개발자 이메일을 꼭 입력할 것.

## 3. 앱 만들기
Play Console → 앱 만들기
- 앱 이름: `listing/title.txt` (CPA Concept Lab: 공인회계사 1차)
- 기본 언어: 한국어(ko-KR)
- 앱 또는 게임: **앱** / 유료 또는 무료: **무료**
  - ⚠️ 한 번 무료로 게시하면 유료 앱으로 바꿀 수 없다.
- 선언(개발자 프로그램 정책·미국 수출법) 동의

## 4. 앱 설정(대시보드 '앱 설정' 항목)
| 항목 | 입력 |
|---|---|
| 개인정보처리방침 | 2단계에서 만든 URL |
| 앱 액세스 권한 | **모든 기능을 특별한 액세스 권한 없이 사용 가능**(로그인 없음) |
| 광고 | **아니요, 광고가 없습니다** |
| 콘텐츠 등급 | 아래 5절 |
| 타겟층 | **만 18세 이상**만 선택(성인 수험생 대상 — 아동 대상 아님, 가족 정책 대상 아님) |
| 뉴스 앱 | 아니요 |
| 정부 앱 | **아니요**(국가기관이 만든 앱이 아님) |
| 금융 기능 | 해당 없음(금융 서비스·대출·투자 기능 없음) |
| 건강 | 해당 없음 |
| 데이터 보안 | 아래 6절 |
| 앱 카테고리 | 앱 → **교육** |
| 연락처 세부정보 | 이메일(필수) — 개발자 본인 이메일 입력 |
| 스토어 등록정보 | 아래 7절 |

## 5. 콘텐츠 등급 설문(IARC)
- 카테고리: **참고 자료, 뉴스 또는 교육**
- 폭력·성적 콘텐츠·욕설·약물·도박·공포: 모두 **아니요**
- 사용자 간 상호작용·콘텐츠 공유: **아니요**(채팅·게시판·사용자 생성 콘텐츠 없음. 오류 신고는 사용자가 고른 메일 앱으로 보내는 것뿐)
- 위치 공유: 아니요 / 디지털 상품 구매: 아니요
- 예상 결과: 전체이용가 수준(최종 등급은 설문 결과를 따른다)

## 6. 데이터 보안(Data Safety) — 실제 구현 점검 결과
| 질문 | 답 | 근거 |
|---|---|---|
| 앱이 필수 사용자 데이터 유형을 수집하거나 공유하나요? | **아니요** | 인터넷 권한 없음, 서버·분석·광고 SDK 없음 |
| (위 답에 따라) 수집 데이터 유형 | 없음 | |
| 전송 중 암호화 | 해당 없음(전송 없음) | |
| 데이터 삭제 요청 방법 | 앱 내 '학습데이터 삭제' 또는 앱 삭제 | 계정 없음 |
참고: Android 자동 백업(사용자 Google 계정)과 사용자가 직접 보내는 오류 신고 메일은 개발자가 앱을 통해 수집하는 데이터로 보지 않는 것이 Play 안내다. 처리방침에는 두 가지를 모두 적어 두었다.

## 9. 테스트와 출시
1. **내부 테스트** 트랙 → 새 버전 만들기 → **Play 앱 서명** 사용(기본값) → `CPAConceptLab-1.0.8-release.aab` 업로드 → 출시 노트(`listing/release-notes-1.0.8.txt`) → 테스터(본인 Gmail) 추가 → 출시
2. 테스터 링크로 휴대폰에 설치해 확인(아래 10절)
3. **비공개 테스트**: 2023년 11월 이후 만든 **개인 개발자 계정**은 프로덕션 출시 전에 비공개 테스트(최소 12명이 14일 이상 참여)를 거쳐야 한다. 조직 계정은 해당 없음. 현재 요건은 Play Console 대시보드 안내를 따른다.
4. 프로덕션 → 출시 검토 제출(심사는 보통 며칠)

## 10. 설치 전 꼭 알아둘 것
- 지금까지 받은 **디버그 APK와 서명이 달라서** 같은 폰에 Play 버전을 덮어 설치할 수 없다. 기존 기록을 옮기려면:
  1) 기존 앱: 설정 → 학습 데이터 → **전체 데이터 백업** (파일 저장)
  2) 기존 앱 삭제 → Play 에서 설치
  3) 새 앱: 설정 → **백업 데이터 복원**
- 이 릴리스 빌드는 실기기·에뮬레이터에서 실행해 보지 못했다(작업 환경에 에뮬레이터 없음). 내부 테스트로 설치한 뒤 다음을 직접 확인하자:
  첫 실행 안내 → 홈 → 개념 상세(간단 요약·상세 학습) → 문제 풀기 → 오답노트 → 설정(목표·복습 주기) → 백업 저장 → 앱 재실행 후 기록 유지.
